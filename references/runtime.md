# 本机执行与版本

## 发现与只读检查

先检查现有工具连接与工程脚本。CLI 找不到 Blender 时查看 `/Applications` 与 `~/Applications`，再根据真实文件选路径，不假定全局 `blender` 命令存在。一次 macOS 测试在用户级 Applications 目录发现 Blender 4.5.3 LTS；这不是跨机器固定路径，后续需重新探测。

用当前实际版本确认节点、修改器、渲染器和导出器。查不熟悉或版本敏感 API 时优先该版本官方 Blender 文档和 RNA 探测。不要仅凭作者环境版本声明本机支持。

后台读取示例；把尖括号内容替换为已确认路径，不直接执行占位文本：

```text
<Blender绝对路径> --background --factory-startup --disable-autoexec --python <Skill目录>/scripts/inspect_scene.py -- --input <源工程.blend> --output <项目检查目录>/scene-inspection-v01.json
```

这个脚本只打开与检查，不保存工程、不渲染、不运行嵌入文本。输出是依赖与配置快照，不是完整拓扑/动画验证。CLI 的新版本、未知节点或渲染器警告必须与 JSON 一起解释。

## 修改与渲染

根据现有授权在副本或新版本操作；显式加载目标工程，先检查当前场景、相机和输出路径。不要默认清空 World、删全场或开启第二个可见实例。后台新建 fixture 可使用 factory startup；生产工程仍以其源文件为基底。

复用本项目现有批处理或 MCP 执行链，脚本只操作声明的对象/集合。批处理与 UI/MCP 不同时写同一工程。失败先检查加载、路径、版本、缺失依赖和实际退出状态，未排除重复提交风险前不自动重跑外部生成。

对照渲染固定场景、相机、帧号、镜头/投影、分辨率与裁切、色彩管理/曝光、光照和采样策略。若本轮目标就是改变其中一项，在审阅记录说明变化，不把它归为另一项改善。

## 导出与实时运行

Cycles 材质节点、程序纹理、体积和 NPR 不会因为保存 GLB 就自动成为等价网页效果。按目标运行端验证实际支持；必要时用可追溯的烘焙、简化或运行端材质实现，并对照同机位画面。导出前后分别检查坐标、单位、法线、实例、材质、透明度和动画范围。

仅在用户需要实时交付时检查碰撞、移动控制器与性能，不为静态图额外搭建运行端。软件升级、第三方组件安装与资产购买由当前任务授权和工具权限决定，版本差异本身不是升级授权。

## 长渲染补充

动画试渲与队列恢复见 [相机与渲染](camera-and-render.md)。后台启动异常时先取日志定位：例如本机共享文件列表/书签或 Python ABI 问题，不能由“窗口没有出现”直接推断 Blender 未安装。使用 Blender 自带 Python 或已验证兼容的 bpy 运行时，不把系统 Python 版本当作兼容证明；本机特殊启动补丁不作为公开 Skill 依赖。
