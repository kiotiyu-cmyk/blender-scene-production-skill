# 互动场景与展示素材

本页仅用于同时交付可行走场景或从互动场景制作影像的任务。静态 Blender 任务无需执行这些步骤。

## 资产与运行端分别验收

用户提供 GLB 或已有单体图时，优先检查并复用确认的资产：尺寸、轴向、姿态、材质、UV、接触点和可见轮廓。装饰对象生成成本高时可以使用用户已授权的资产生成服务；不要把简单几何占位持续当作精修。具体商业服务、付费和上传权限由当前授权决定，不硬编码到 Skill。

网页材质、灯光、程序水和雾不会自动回写 Blender；Blender 的 Cycles 节点也不会自动等价导出。维护源工程、导出资产和运行端各自版本关系。用户要求拍摄“现在的最终效果”时，先同机位对照，补齐缺失的云、材质和灯光，再安排长渲染。

## 行走和摄像机

使用连续导航高度或平滑相机高度处理踏步，不依靠角色穿透台阶。角色脚底、胶囊/碰撞体、头肩与第三人称镜头各有包络，分别检查上行、下行、转身和到平台的过渡。足部贴合不能补救错误的导航面；摄像机避障不能代替角色碰撞。

路线修改或新增道具之后实际跑一次完整自动漫游；再检查自由行走中容易进入的边缘。空间采样报告不等于真实控制器验证。

## 分站故事与镜头

讲述按空间触发点组织，例如壁画、织机、剧场、泉水。每站记录进入范围、角色停留位置、镜头段落、字幕/音频、动态效果及退出后的状态。避免把后几个站的台词在一个点一次讲完。

用明确状态管理接近、演出、结束和恢复行走，防止自动漫游越过触发器、音频重叠或重复播放。镜头可按整站音频时长或独立时间轴连续运动，字幕换行不应让镜头跳变。中断、重播和恢复要回到一致状态。

局部叙事变化绑定具体对象或区域，例如小泉眼与壶口的酒色渐变；不能为方便而全局染红水池。保持下游变化的时间与空间关系可读。

字幕按用户目标设备实际预览：双语逐行、行宽、字号、边距与底部控件避让一起检查，不仅改 CSS 数值。无大卡片的要求可以用轻量描边/阴影维持可读性；字幕不应挤掉主体。配音按用户提供的正文与语言制作，不擅自添加考证标签；先确认语音模型真实语言支持。凭证只留在合适的本地配置中，不写进客户端、生成清单或公开仓库。

## 动态效果与声光统一

静帧里有纹理不等于视频里有运动。水流方向、速度层次、碎浪、冲击泡沫和雾应有非机械的时空变化；避免等距正弦波整片同相移动。检查近景与远景，以及开头和结尾是否突跳。使用静态水网格时明确范围，不称作流体模拟。

火焰需有软边、亮芯、形变和温和的不规则明暗，避免橙色实体锥体与独立闪光不对应。环境云、主光方向、投影与场景中实际高光保持一致；整体日光与局部烛光分层，不为突出灯具破坏总曝光。

背景音乐需有实际来源、许可范围及音量控制；旁白开始时适度降低音乐。用户没有要求声音时不自动引入音频生产。
