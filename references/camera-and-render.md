# 相机与渲染交付

## 在长渲染前锁定交付

沿用用户最新决定，记录画幅、真实输出像素、帧率、片长、渲染引擎、是否带声音/UI，以及合片和分段需求。用户改画幅后，重查所有关键镜位，不能仅改输出尺寸或裁掉旧画面。示例：4:3 可用 3840×2880；这是一次项目选择，不是所有任务的默认值。

区分 Blender 相机渲染、Blender 离屏/视口录制和网页录屏。Cycles 静帧、EEVEE 动画、网页实时材质允许服务不同交付，但分别标明方法并检查差异。不要把低清帧放大命名成原生高清，也不要把单帧水体称作完整流体动画。

先试渲外景、最窄通道、细节特写和最高负载画面，再选择整片参数。记录冷启动与热运行帧耗时、内存、单帧写盘/编码时间；据此估算整段成本。4K 单帧成功不证明数千帧可稳定输出。需要降低规格或改变已要求的渲染器时，说明影响，不能暗换交付标准。

## 运镜设计与通道检查

- 把环绕、入口、壁画扫视、楼梯、道具特写、剧场和拉远组织成可独立剪辑的镜头；一镜到底仅在用户需要且空间允许时采用。
- 相机位置与注视点分别设计。壁画按空间顺序缓慢扫过，不按每句旁白瞬移；道具特写可先下摇到结构细节再抬回主体。具体节奏服从用户意图。
- 楼梯跟随连续的相机轨迹，而不是直接复制每级踏步高度。移动方向、提前转向量、视线与焦距一起检查，避免尚未到平台就转向近墙。缓入缓出能减速，但不能修复穿墙路径。
- 角色可行走包络与相机包络分别检查。第三人称应检查头肩、相机后退距离和转角墙；有需要时缩短跟随距离或转到前方机位，保持剪辑方向可读。
- 池底、看台、顶板、厚杯壳等后加几何也参与通道检查。发现遮挡时确认命中的对象和距离，先在制作副本修实际净空，再改镜头；不要只缩小近裁剪面来掩盖穿模。
- 在窄通道、转弯前后、俯仰峰值、过门和焦距变化处加密采样。射线只是诊断，必要时检查近裁剪平面/相机包络。先审低成本整段运动，解决贴墙、遮挡和急转后再上高清。

## 场景优化与画面保护

统计唯一网格与实例引用，避免把每个实例的面数相加后误认实际内存。针对瓶颈优化共享网格；保留 UV、材质槽、法线和近景轮廓，保护原件。

不要默认批量 Join 会更快：对象坐标、Generated 坐标和材质映射可能改变，纹样可能丢失。优化前后用同镜位查看杯耳、薄织线、雕像面部、透明水和植被；画面或速度无收益就回退该优化。

## 稳定渲染与状态

按镜头或可重建批次输出。记录源工程/资产指纹、相机范围、画幅、引擎、色彩管理和采样；续渲时核对这些字段及已完成文件，不因同名视频存在就跳过。

运行状态区分：已编排 → 试渲通过 → 渲染中 → 编码完成 → 技术校验通过 → 画面审阅完成。进度来自实际帧号/文件；后台任务启动、JSON 写出或进程退出不能单独证明完成。

临时视频用独立名称，编码完成且校验通过后再改为交付文件。失败时保留日志、完整片段和检查点，不将未完成文件拼入成片。GPU 长批次出错时缩小批次或重启该渲染进程，先试单片段；避免多实例同时占用 GPU 或写同一工程。

如果任务需要长时间后台继续，提供实际输出目录、当前进度及是否需要保持应用运行。只有确实建立后续通知机制时才承诺稍后通知。

## Blender 4.5 离屏路径的局部验证经验

此节只在选择原生 GPU 离屏输出时读取；先按实际 Blender 版本做小试验，不把它作为通用必选渲染方式。

- 使用真实相机视图/投影矩阵，显式设置场景灯光、世界和色彩管理，关闭编辑叠加层。材质预览与 Rendered 模式的结果、性能可能不同。
- 镜头或帧变化后重新累积足够采样，再读取像素。静止相同视图的缓存绘制速度不能作为动画逐帧速度。
- 使用 `GPUOffScreen` 时保留有效 GPU/UI 上下文。窗口区域变动或关闭可能使任务失败；无 UI 批渲优先标准渲染路径。
- 读取颜色 Buffer 后，显式设置 `buffer.dimensions = width * height * 4`，再转 NumPy 并 reshape 为 `(height, width, 4)`；转换前检查 dtype。按接收方坐标约定翻转行序。一次实际测试中未展平的 UBYTE Buffer 导出产生了错误条纹，展平后正确。
- 首帧经最终编码路径读回，检查尺寸、上下方向、RGBA、透明度及明暗；不要对已做色彩管理的像素再次套显示变换。高分辨率输出也需这项检查。

这些是一次 Blender 4.5.3 / Apple Metal 测试的经验，其他平台、版本、渲染器仍需验证。

## 白模到成品

用同一镜位、同一尺寸依次显示主形、建筑、道具、材质、植被水体和最终氛围；按作品需要增减阶段。尽量用集合/场景和材质覆盖实现，不破坏源对象关系。各阶段既可交付独立图片，也可交付快切视频。

拆解当前场景得到的阶段展示不是历史制作录像；交付时说明。只有镜位、画幅、灯光和场景状态确实匹配时，才可复用已成功的终态帧代替一次失败的重复渲染，并记录来源。

## 验收与素材打包

使用 `inspect_video.py` 核对实际视频流、像素、帧率、帧数、时长；需要时完整解码。抽帧接触表用于定位问题，仍需播放完整批准范围以检查急转、跳切、闪烁和遮挡。技术通过与视觉通过分别记录；看到缺陷后回修相应镜头，不把“渲染完成”写成“成片验收完成”。

用户要求汇集素材时，保留版本和相对目录，并把原始录制、测试/失败试录、已剪片段、成片分清。项目明确引用的外部原始录屏可纳入，避免扫描无关私人目录。清单写尺寸/大小/来源及必要备注；归档不必转码。大包使用支持大文件的 ZIP64，校验全部条目；同名包保留旧版。不要上传项目素材或凭证作为 Skill 发布附件。
