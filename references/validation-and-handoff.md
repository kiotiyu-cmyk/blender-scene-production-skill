# 验证与交付

## 与修改范围对应的证据

| 检查 | 可支持的结论 | 不能自动支持的结论 |
| --- | --- | --- |
| 依赖/材质快照 | 图片存在或已打包，外部库与节点配置情况 | 材质观感正确或高版本无损兼容 |
| 中性视图与必要正交/剖切 | 轮廓、厚度、连接与结构疑点 | 全部视点、全部角色或动画均无穿模 |
| 固定机位实渲对照 | 该帧下特定改动的画面效果 | 整个世界、最终剪辑或自由行走通过 |
| 静态路线采样 | 已声明路线与包络范围内的净空 | 真实控制器上台阶、转身和自由探索通过 |
| 全段动画与重点帧 | 当前运动中的连续性与可见缺陷 | 自动穷尽所有碰撞或模拟边界 |
| 实际运行端测试 | 当前设备与场景条件下的交互与性能 | 其他设备均流畅或 Blender 材质等价导出 |

针对本轮区域检查法线、零面积/重复面、明显交叠、修改器状态、连接与贴图尺度。闭合体、水体和厚壳按其用途检查；开放布面不强制闭合，静态硬表面不强制全四边面。检查报告写出范围、容差来源、允许接触与未覆盖项。

运动工作按整个批准范围查看视频；有穿越或高速运动时检查中间帧与包络，不能只检查起终点。实时项目实际运行目标引擎，验证导出资源、路线与控制器、声音/交互（若属本轮）、帧率或帧时间及加载开销。

## 画面对照

`compare_review.py` 使用 Pillow，输入两张真实图片，输出左右对照；宽高比一致时另输出叠图与差图。不同分辨率会等比统一到较小输入，宽高比不一致则不生成差图以免拉伸造假。

```text
python3 <Skill目录>/scripts/compare_review.py --before <改前.png> --after <改后.png> --output-dir <项目审阅目录>/comparison-v01
```

输出目录每轮唯一；脚本拒绝覆盖已有文件。读取 `comparison.json` 的比较限制，再检查缩略图中的层次与全尺寸细节。文件像素误差不能证明物件身份、真实材质、空间连接或审美正确；脚本始终要求人工/代理语义审阅。

参考图与实渲可用相同工具，但先明确比较的是重建目标还是前后实验。曝光、摄影机、裁切、光照和渲染设置由制作记录核对，脚本不能从像素替代这一检查。

## 交接记录

遵循现有目录与版本规则。若项目缺少本轮审阅记录，写一份简短记录即可，包含：

- 目标及来源，受保护内容和本次修改范围；
- 源工程、新工程、机位/帧号和关键渲染条件；
- 改动原因、前后实渲、已验证结果和未验证项；
- 当前状态是内部检查完成、候选待审还是用户已确认，以及下一动作。

不用另一套私有状态文件代替项目 `00_brief.md`。不因本 Skill 的技术检查通过而擅自更新最终视觉或发布关卡。若原有工程还存在未解决的问题，交付已完成的局部并清楚说明限制，不把完整流水线启动称为完成。


## 视频文件与归档

用 [相机与渲染](camera-and-render.md) 的阶段状态报告进度。`scripts/inspect_video.py` 只检查实际媒体和指定规格，可选完整解码；始终要求另做视觉审阅，不生成审美“通过”分数。格式检验失败或发现穿墙、遮挡、闪烁时，不把启动重渲染写成已解决。

归档可附文件清单、SHA256 和条目 CRC 验证；这只能证明交付完整性，不能替代素材质量检查。用户只要求打包时，不擅自转码或删除试录。


调用示例（参数按实际交付改写；报告文件必须是新文件）：

```sh
python3 scripts/inspect_video.py --input scene-orbit.mp4 --output orbit-check.json --expect-width 3840 --expect-height 2880 --expect-fps 24 --expect-frames 288 --expect-duration 12 --decode
```

工具依赖可执行的 `ffprobe`，完整解码另需 `ffmpeg`；可用 `--ffprobe`、`--ffmpeg` 指定路径。退出码 0 表示本次技术检查通过，1 表示媒体/规格检查失败，2 表示调用参数或依赖不满足。帧率检查为视频流平均帧率，不等于逐帧时间戳节奏检查。
